Every rollback names whou:, whent: and wherer:.

You join after the damage is done. A player was killed, the loot went into a hidden chest, and some of it was duped. This guide walks through the cleanup with CoreProtect, step by step, without touching anyone else's things. Every /co command and parameter is below it.

    Recall the lookup instead of retyping it

    Open chat with T, press ↑ to bring back your last command, change l to rb, press Enter. The parameters stay identical to the lookup you just checked.

    Use the short forms

    /co lookup/co l
    /co rollback/co rb
    /co restore/co rs
    /co inspect/co i
    lookup, radius 5/co near

    Stack time units

    t:2h30m, t:5d2h, decimals like t:1.5h, or a window like t:1h-2h for between one and two hours ago.

    Count before you read

    Add #count to see how many rows match. Page with /co l 2, or show 20 lines a page with /co l 1:20.

    Click instead of flying

    On recent versions the coordinates in lookup results are clickable and teleport you there. That needs coreprotect.teleport.

    Select the exact area

    With WorldEdit, r:#we limits a command to your selection. Big rollback? #silent keeps chat short.

        Purge and database tools

        Purging deletes old log data for good. After a purge, lookups and rollbacks cannot reach that time any more, so keep enough history to investigate the cases you actually get.

        /co purge t:<time> r:<world/radius> i:<include> e:<exclude> a:kill
        30 daysYoungest data you can purge in-game
        24 hoursYoungest data you can purge from the console

        Common purges

        Rules for radius purges

        • Only block data and entity-kill data are affected, so combine the radius with i: or a:kill.
        • In-game only, and always in the world you are standing in. It cannot be combined with a world such as r:#world_nether.
        • Capped by max-radius in the config. r:50x10 also limits height to 10 blocks above and below you.

        Rules for kill purges

        • Kill logs can be purged on their own on SQLite, MySQL and DuckDB. Removing a kill also removes the saved entity data a rollback would use to bring the mob back.
        • e: only takes entity types. It cannot be combined with entity types in i:, or with only block types in i:.
        • a:kill cannot be combined with block types in i:.

        What #optimize does on each database

        BackendEffect of #optimize
        SQLiteNot needed. A manual purge already rebuilds the file and frees the space.
        MySQLAlso removes saved entity data in the purged range that no kill points to any more (needs the CREATE TEMPORARY TABLES privilege), then optimizes the tables to free space.
        DuckDBNo extra effect. The purge runs in one transaction and checkpoints afterwards.
        ClickHouseAlso runs OPTIMIZE TABLE ... FINAL. Plain time purges already drop whole monthly partitions.

        #optimize arrived in v2.15. It can make MySQL and ClickHouse purges much slower and is usually unnecessary.

        Moving to another database

        /co migrate-db <sqlite|mysql|duckdb|clickhouse> [--full-validation]
        • Console only.
        • By default it checks all table statistics, samples about 1% of each large history table and fully compares small tables. --full-validation compares every copied row.
        • The target must hold no CoreProtect data, a DuckDB target must be a new file, and database-lock must stay enabled.
        • When it succeeds, database-type in config.yml is updated for you.
        • SQLite to MySQL and back needs a 23.0+ Patreon build. Anything involving DuckDB or ClickHouse needs 25.0+.

        Full steps: docs.coreprotect.net/database-migration

        Fine print in the official docs

        • a:login vs a:session. The docs' examples use a:login, but the action list has a:session, a:+session and a:-session. This guide sticks to the listed actions.
        • World names. World targets appear as r:#world_the_end, r:#world_nether, r:#nether and r:#world. Test the name with a lookup on your server before a rollback.
        • /co near and /co undo are listed as alias commands with no further syntax.
        • #optimize is documented under purge, not in the hashtag list.
        • f: and hashtags are missing from the lookup, rollback and restore syntax lines but are part of the shared parameter list.
        • Example output on this page is illustrative. Exact wording and colours differ between CoreProtect versions.
